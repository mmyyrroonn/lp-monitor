# 日志优先的热度监控：取消逐块Header

日期：2026-09-08。用户最新要求：主要看哪个RWA/关联Meme/池热，及时发现短时机会，允许批量追块，不要求精确模拟LP。

本决定已纳入主设计和P0–P6，替代此前“每块必须保存Header”的要求。当前修改仅为架构、计划和公开RPC验证资料，应用未实现。

## 为什么以前取区块头

原先用它补事件时间、检查parentHash连续性、维护严格的逐块账本。事件排序和去重本身不需要另取Header，logs已有blockNumber、blockHash、transactionHash、transactionIndex和logIndex。成交金额与加减池动作来自Uniswap事件。

热度监控改为范围账本：每2秒取相关logs；少量端点用于知道链头高度、校验上次cursor和定位分钟；不保存所有区块的Header，不下载每笔交易/receipt，也不重演AMM。

## 新实测：日志时间字段有值但不可用

2026-09-08 03:44:26 UTC（北京时间11:44:26附近），公共端点的57,378,748–57,378,767共20块，V4 Manager返回55条事件，涉及18块。**55条blockTimestamp均为0x0**。抽样首尾有事件块：日志blockHash与块头一致，但真实块头时间分别为1,788,839,058和1,788,839,060，与0不符。

原始请求/响应及摘要保存在[时间字段证据](evidence/2026-09-08-log-timestamps.json)。本次未经过SDK格式化，问题在原始端点响应中已经存在；不推断服务端内部原因。

前一轮只确认字段存在，不能据此认定可作为事件时间。当前[Execution API](https://ethereum.github.io/execution-apis/api/methods/eth_getLogs/)列出此字段，但实现质量必须实测；用户自己的RPC需要重新验证。有效时间可直接用，否则走下面的分钟边界方案。

## 不逐块查询，也能得到分钟统计

假设少量端点证据确认：块100的链时间在11:30，块120仍在11:30，则其中相关日志都归11:30分钟桶。跨越11:31时，二分查找第一个timestamp>=11:31:00的块B；核对B-1与B，前后日志即可正确分桶。

多个块可以同秒，必须取第一个满足条件的块。该算法依赖本链区块时间非递减；采样和运行中的端点核验发现矛盾时标unresolved，不能按平均出块速度猜时间。

- 正常每批读取链头与上次cursor的少量端点；不随块数线性读取Header。
- 只有跨分钟才补分钟边界查询，缓存结果。5m/15m指标从1m桶合成。
- 保留原始事件顺序；不知道精确秒数时exactTimestampSec=null，时间质量标minute。
- 本分钟累计每2秒更新，可直接发候选提醒；完整分钟/5m桶用于比较基线及确认。
- 历史回填仍按历史分钟归桶，不能用今天的到达时间，更不能把断线补回的一批成交当当前突然放量。

## 具体保留与删减

| 能力 | 首版决定 |
|---|---|
| RWA两侧新池发现、Swap、Mint/Burn/ModifyLiquidity | 保留，按范围两遍读取 |
| 本分钟累计、完整1m/5m量、Swap数、不同tx数、放量倍数 | 核心交付 |
| 新池、旧池再热、持续活跃分钟、加减池动作 | 保留 |
| 每块Header、完整parentHash链、完整池状态模拟 | 取消 |
| 历史slot0/StateView、feeGrowth、LP净费、IL/净收益模拟 | 移出首版 |
| 身份/decimals/池元数据 | 初次或变更时只读查询并缓存 |
| 原始相关日志、扫描cursor、近期重扫与修订 | 保留，避免重复量和假热度 |

真实交易者数、TVL、美元流入、LP收益率不能仅靠这些日志准确得到。不同tx数不等于不同钱包数；加减L不等于美元本金。未计价RWA不按原币数量跨资产排名。

## 少量一致性检查

每批固定end anchor后检查上次成功cursor，默认重扫近期20块；重组超出重扫范围时由cursor hash变化发现，沿已有稀疏检查点恢复。完整重扫发现旧日志消失，就从有效集合和热度中扣除；原始版本仍保留。

分片失败/截断嫌疑不当作空结果删除旧日志，过滤范围变更有单独覆盖记录。提醒默认可修订，不用20块或任意固定深度称最终确认。[EIP-234解释空日志与重组的边界](https://eips.ethereum.org/EIPS/eip-234)

这是以RPC为信任来源的实用范围修正，不是独立校验全链。完全取消时间/高度读取并不合适：空结果时仍要确定扫到了哪，以及把历史放量放回正确分钟。

## 成本与历史验证

正常稳态每2秒约2次端点读取，加D个发现分片、O个操作分片；粗略方法数为(2+D+O)/2次每秒，另加跨分钟定位、metadata和重试。若D=4、O=2，约4次/秒加附加项；这只是容量规划，需在实际过滤规模/RPC上测量，不能承诺固定月费。

此前约10块/秒样本下，全块头约10次/秒；现在端点基础约1次/秒，再加少量分钟边界，取消了与每个新块绑定的主要开销。省的是方法数量，供应商CU/流量价格仍另算。

历史评估改为分钟级：完整分钟数据在分钟结束后才用于决定，统计后续15/60/180分钟成交与持续时间，保留死亡、再热和缺口样本。它能够比较“多少候选很快冷掉”，无需精确模拟仓位收益；不能据此报告秒级最早发现时间。
