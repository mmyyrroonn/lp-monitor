# 代币热度监控台

前端复用现有 SQLite 录制证据。页面提供热度排行与表头点击排序、1/5/15/60 分钟窗口、15/30/60 分钟热力图、历史分钟回看、代币与池详情、本机自选以及运行状态。

## 启动

在仓库根目录执行：

```powershell
pnpm dashboard --db data/recorder.sqlite
```

该命令先构建再启动本地 HTTP 服务。打开 http://127.0.0.1:8787 。只监听本机，Ctrl+C 停止。已有构建也可以使用：

```powershell
pnpm lp dashboard --db data/recorder.sqlite --port 8787
```

参数支持 `--config`、`--watchlist`、`--metadata`、`--db`、`--port`，默认值与指标 CLI 相同。页面不会调用 RPC、启动采集、更新投影或发送提醒；连接已有采集时必须使用同一数据库、配置与观察名单。只启动网页不会产生新行情。

默认观察名单是 `config/watchlist.stocks.json`。旧 AMC 数据必须显式指定 `--watchlist config/watchlist.amc.json`；跨名单的空状态不代表全链没有交易。首版分类仅来自登记的 RWA 股票；未知对手币展示合约地址，不推断 Meme 身份。

默认 `follow` 从启动时最新块开始，重启不会追赶停机区间；无需删除原库。首批窗口会显示数据不足，随真实覆盖积累变为可用。统计仅包含本地已登记池及启动后新发现的池，未登记老池的覆盖未知。

## 实时数据与旧库

普通模式要求存在新鲜的增量投影。当前带指标的采集入口为既有 `follow --notify local`；该选项同时启用已有本机提醒。运行方式与预算见 README，前端本身不替用户启用它。仅有原始日志或旧的 `project --rebuild` 游标时，普通模式会明确提示投影缺失或过期。

如果已有数据库只有旧版离线投影，可显式采用旧库只读快照：

```powershell
pnpm dashboard --db data/p3-acceptance.sqlite --watchlist config/watchlist.amc.json --legacy-snapshot
```

该模式首次读取时执行旧版完整来源核验，**这段核验在服务进程自己的线程上同步运行，期间整个 HTTP 服务停止响应——网页本身、静态资源和其它 API 都不返回任何字节**，实测在生产库上超过 32 秒仍未结束（响应为 `http=000`，即完全没有响应）。数据库越大越久，且没有超时上限；只有首次核验结束后才恢复正常服务。通过后仅保留最近 180 分钟及 120 秒报价上下文。后续使用同一个只读连接，以 SQLite `data_version` 核验源库是否发生写入。一旦写入或最初核验失败就标记过期，重启才会重新核验，不自动更新旧投影。如果存在新鲜增量游标，则优先走普通有界路径。

旧库读取失败时，页面保留准确的失败状态。不要把旧数据时间当作当前时间。已有投影确实过期时，若需要重新投影，建议先通过现有 `backup` 命令生成独立副本，再对副本显式执行 `project --rebuild`；前端没有源库修复按钮。

## 指标口径

- 所有窗口使用已接受的链上时间 T，区间为 `(T-duration,T]`；比较对象是前一个等长窗口。页面刷新时间与源时间分别显示。
- 事件时间只有分钟精度，分钟桶是闭区间 `[m, m+59]`：实时窗口的结束点取最后一个完整分钟（最多滞后 59 秒），不会落在正在走的分钟中间；不足一个完整分钟的新 run 仍以链上时间为结束点并保持保守。热力图照常展示当前正在走的这一分钟，标注“分钟尚未完整”。
- 交易数按代币在窗口内跨池去重；Swap 事件数在详情中单列，交易数不是独立用户数。
- 同一共池分别计入相关股票的参与量，并保留各自估值；不同股票金额不能直接相加作为去重后的全市场成交额。
- USDG 等值量采用现有报价与精度证据。USDG=USD 只是展示假设。缺报价、缺精度或覆盖不足，仍显示 `—`。
- 已完整采集且没有交易才显示 0。热力图缺失分钟使用灰色斜纹，未完整分钟用另一种斜纹；图形不会跨缺失分钟连线。
- 详情中的“最后精确 Swap 时间”仅限保留窗口内可证明的观测，没有精确秒数时显示未知。

排行是描述性观察，不是经过收益验证的信号。阈值固定并直接显示在页面：

| 视图 | 优先条件 |
| --- | --- |
| 突然升温 | 当前至少 10 笔、较前窗至少 2 倍、增量至少 5 笔；满足后按绝对增量排序 |
| 新增活跃 | 前窗完整且为 0、当前大于 0；不输出无穷大百分比；至少 10 笔才进入升温优先区 |
| 持续热门 | 当前至少 10 笔，最近 5 个完整分钟至少 4 分钟有交易，且没有缺失分钟 |
| 正在降温 | 前窗至少 10 笔、当前下降至少 50% |
| 交易最活跃 | 当前窗口交易数；可切换已知 USDG 等值量 |

这些视图优先排列符合条件的代币，其他行仍保留，以便检查安静和数据不足的对象。前窗未知时不会推算变化百分比。

表头中的 `# / 代币`、当前窗口交易数、USDG 等值量、池四列可以点击排序：第一次点击按该列排序，数值列默认降序、名称列默认升序，再点一次反向，`aria-sort` 标出当前列与方向。点击任一视图按钮即回到视图排序。排行上方的“按估值排序”复选框与 USDG 等值量列是同一个状态：勾选等于该列降序，仍只在“交易最活跃”视图下可用。当前窗口交易数或估值不可用的行（显示 `—`）在升序与降序下都排在末尾，不当作 0；同值行依次按名称与合约地址排列，刷新不会改变它们的相对顺序。

## 热力图与交互

热力图始终锚定最新已录制源时间。默认展示最近 30 分钟内单分钟峰值最高的 12 个代币，可展开全部。绝对模式使用跨代币统一色阶；相对模式各行按自身峰值归一化，颜色不能跨行比较。

点击完整分钟最后一秒对应的格子，排行与详情切换到该截止点。历史内部缺口保留可检查状态；超出保留起点或未来的格子禁用。历史回看属于用当前有效证据重算，不是“当时已知信息”的策略回放。当前源码修订和重组后的有效证据会反映在结果中。

自选保存在浏览器本机 `localStorage`，按链和监控 scope 隔离，不会写入数据库。服务每个快照最多缓存 5 秒，最多缓存 8 个选择时间；同一请求合并、不同时间请求串行处理。页面每 5 秒发起一次完成后再等待的刷新，不重叠请求。鼠标或键盘正在查看排行、键盘位于热力图或详情打开时，保留当前位置，稍后应用新快照。断线时保留上一份结果并明确显示错误，恢复后自动更新。

## 运行状态

运行页显示最近侧写的链头差、运行状态、采集/投影区块、处理耗时、RPC 方法累计、本机提醒积压以及 DB/WAL 大小。侧写缺失/过期时显示未知或标注原观测时间；旧链头不是当前链头，单次处理耗时不是端到端延迟或 p95。
