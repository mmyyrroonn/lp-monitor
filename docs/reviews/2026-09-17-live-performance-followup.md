# 2026-09-17 性能优化续作

本轮按上一份修复报告的计划，完成覆盖证明快速路径、时间证据窄列读取，以及信号配置和审计内容复用。固定 400 活跃池的 8 万 / 16 万目录离线基准均已达到原定目标；全活跃压力场景和启动仍有明显成本。

## 代码修改

1. `src/ingest/completeness.ts`：全部分片覆盖整批区间时，直接验证选择器非空及组合数上限，不展开地址/topic 笛卡尔积。部分区间继续使用原算法；保留不同地址、不同 topic 不能借用覆盖，以及中间组合数超过 100,000 的拒绝规则。异常选择器形状回到原校验路径。
2. `src/storage/raw-store.ts`、`src/metrics/coverage.ts`：覆盖检查只读取区块号和时间归属；实际区块范围与声明时间范围取并集，仍检查旧区块错误归属新分钟。多个 active family 的同一日志去重，缺失归属仍为 undefined。`logTimes` 也只读取构造日志引用所需的列。
3. `src/signals/engine.ts`、`src/signals/project.ts`：每批准备一份独立配置快照并计算一次版本，供所有池及历史窗口使用。原配置原地修改后，新一批会读取变化。相同审计字节在同次投影事务内复用已验证的载荷引用，每个池仍保留独立状态和审计行；缓存最多 64 个键、每键最多 65,536 个 UTF-16 单元，新事务重新验证载荷。
4. `src/ops/work-counters.ts`：新增实际选择器展开、配置版本计算和审计载荷处理计数，默认关闭。

信号阈值、滚动窗口、缺失数据含义、冷池事实、通知边界与默认 V4 pool-ids 模式保持原契约。

## 正式离线基准

与前轮一致：194 股票、181 分钟覆盖、3 轮预热，普通样本为 14 次 fresh、3 次 advance、3 次 repeat，共 20 轮；初始化与 3 个修复轮单列。三组串行运行，期间没有并行跑测试或构建；基准自身的 dashboard worker 包含在测量中。

本地处理使用 `normal.localProcessingMs`，不使用包含 mock 获取和请求准备的 `normal.p95Ms`。内部阶段可能包含子阶段，不能相加。原目标为本地 p95 <2,000 ms、固定活跃量的 160k/80k 比值 <=1.5、预热 HTTP p95 <1,000 ms 且响应 <1 MiB。

| 注册池 / 活跃池 | 本地 p95 修改前 | 本地 p95 修改后 | 降幅 | 初始化修改前 | 初始化修改后 | HTTP p95 修改后 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 80k / 400 | 1,778 ms | 1,310 ms | 26.3% | 76.7 s | 55.3 s | 66 ms |
| 160k / 400 | 2,581 ms | 1,776 ms | 31.2% | 167.1 s | 105.9 s | 42 ms |

两组普通批次均达标；扩容比 1,776 / 1,310 = 1.356。HTTP 最大响应 292,475 字节；HTTP 分布包含普通、预热及修复轮共 26 次请求。

普通批次全目录读取/序列化、选择器组合展开均为 0；每批配置版本计算 1 次，两组的 3 个重复轮估值均为 0。16 万池 projection 阶段 p95 从 1,325 ms 降到 457 ms；该阶段是诊断数据，不能加总冒充本地处理总时间。

初始化之后，首轮预热本地耗时仍分别为 18.5 s / 37.7 s，按原口径排除在普通 p95 外。初始化数字不能代表从启动到首个可用结果的全部等待时间。普通轮峰值 RSS 分别为 2,562 / 3,710 MiB，包含合成目录夹具和 worker，不能作为线上常驻内存或内存下降的证明。

2,000 池 / 2,000 全活跃的 20 轮压力样本：本地 p50 5,082 ms、p95 6,660 ms、最大 6,923 ms，仍有显著成本。前轮 p95 为 7,949 ms，但前轮压力采样曾与两条短测试重叠，故此对照仅作观察，不宣称是严格隔离的提速比例。

完整结果：`artifacts/performance/2026-09-17-followup-{80k,160k,all-active}/benchmark.json` 及同名前缀日志；自动汇总和门槛断言：`2026-09-17-followup-results.json`。

同样的 8,000 池 / 80 活跃池诊断，Node inspector 每 1 ms 采样：

| 阶段 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 目录加载 | 2,006.773 ms | 2,113.323 ms |
| 首次窗口 | 6,131.460 ms | 3,489.437 ms |
| 初始化总计，含夹具构造 | 8,154.130 ms | 5,620.341 ms |

首次窗口降低 43.1%，初始化总计降低 31.1%。这个小样本的普通 5 轮 p95 从 262 ms 变为 279 ms，不能拿它宣称普通批次提速。CPU 采样用于定位历史信号评估中重复的配置准备及审计压缩；没有通过跳过冷池首次事实缩短启动。

证据：`artifacts/performance/2026-09-17-next-init-{before,after}/benchmark.json`、`init.cpuprofile`，入口 `profile-init.mjs`。
