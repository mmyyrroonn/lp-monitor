## What is correct

- V3/V4 decoders reuse pinned official ABIs, preserve signed bigint raw amounts, normalize opposite protocol signs, reject zero/same-sign ordinary trade directions without fabricating amounts, retain raw errors, and check canonical ABI data/topics. Existing V3 decoder API remains available.
- V3 Mint/Burn use positive/negative liquidity units, V4 ModifyLiquidity preserves signed delta/salt, and Collect/Donate remain ancillary. Zero liquidity remains zero. No user-count metric is inferred from actors, and no principal amount is confused with liquidity units.
- V3 fee comes from registration; V4 Swap fee comes from the event. Dynamic Initialize flags remain metadata. ERC-6909 manager-wide ids are not treated as pool ids by the decoder; P1 operation filters only request pool-scoped events.
- Observations preserve last Swap price/tick/L and position, while later liquidity actions only replace lastLiquidityAction. Burn alone does not invent a Swap observation. Out-of-order events and cross-pool inputs have explicit handling.
- Projection exclusively consumes `SqliteRangeStore.activeLogs(scopeId)`. Raw-only failed/incomplete captures are excluded. Scope-filtered logTimes and P1 normalized pool registrations are reused; the discovery-plus-operation registry merge follows the existing P1 recorder contract.
- Rebuild uses one immediate SQLite transaction for the source snapshot, all replacement rows, and projection processing cursor. `read` takes a coherent transaction snapshot and rejects stale input hashes. Hash input covers logs, effective per-log times, pool registrations, accepted ranges, both relevant tips, config version, and projection version. Removal/retiming/registry changes cannot silently return the old projection through this API.
- Typed quantities are persisted losslessly and revived as bigint; ancillary decimal strings retain their intended type. Offline CLI dispatch occurs before environment/RPC setup. Minute-only time stays minute-only, and output explicitly disclaims complete current pool state.
- Migration packaging already copies the entire migration directory, so the new migration is included in builds without another script change.

## Meaningful test gaps and limitations

1. The principal missing V4 projection regression is now implemented and independently green, as recorded above. No additional test is required to close this review.
2. The archived real fixture test correctly discloses synthetic registration metadata for swaps without matching Initialize records. It independently validates real payloads/signs/post-state/Swap fee, but is not proof of historical token identities or historical V3 fee metadata. Preserve this distinction in the acceptance record.
3. Whole-scope replay/hash/serialization is intentional for bounded offline P2. Every rebuild is O(history), and `read` also loads/hash-checks full active history. The cursor payload duplicates the complete event/error/observation result already present in individual tables. This is acceptable for the present phase; it is not yet suitable as a constant-cost live per-pool read or long-running large-history projection path.
4. Projection transaction atomicity is established for the projection processing cursor and derived rows, not simultaneous raw ingestion: P1 accepted cursors can advance before the next explicit `project`. That is safe in the supplied CLI because `read` returns stale-or-missing, but future consumers must not read derived tables directly while ignoring cursor validity.
5. The existing rollback test injects failure at cursor UPDATE after derived replacements and verifies rollback, an appropriate meaningful atomicity test. The current scope does not implement alerts; P1/P2 tests cannot establish future P4 alert-retraction behavior.
