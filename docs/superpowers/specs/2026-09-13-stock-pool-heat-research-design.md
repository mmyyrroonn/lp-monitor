# 股票池完整目录与热度研究设计

日期：2026-09-13。状态：方向已由用户确认，实施计划已编写；代码、迁移与新采集均未执行。

## 1. 用户目标与本轮授权

用户希望知道哪些股票相关池开始变热，并用可核验的数据确定热度提醒标准。用户已接受“完整池目录 + 有代表性的有限历史 + 持续实时采集”的方向，要求先写计划，在新窗口实施。

本窗口仅写设计、计划和交接入口。下一窗口收到“实施计划”时，默认范围为 H1–H4 的代码与离线验证。H5 的实链采集需用户在该窗口给出运行安排；本计划本身不启动采集、不安装服务、不购买数据、不切换线上阈值。

## 2. 决策

- 不做全链区块/交易/收据/执行轨迹归档，不运行历史状态归档节点。
- 先把“有哪些池”与“这些池过去发生过什么”分开：先独立建目录，再按目标日期获取操作事件。
- 第一版完整性限定为已配置且核验过的 Uniswap V3 Factory / V4 Manager，与指定版本的官方股票名单的交集。
- 股票地址出现在 token0 或 token1 均纳入；股票共池按两只股票分别归因，但只保存一份池/事件贡献。
- 池存在、当前流动性、近期活跃、历史覆盖是不同状态。冷池和无交易池不从目录删除；缺口不写成零。
- Pons V2 毕业前 CurveBuy/CurveSell 及其他 DEX 为扩展范围，第一版明确列为 excluded，不静默声称全链股票交易覆盖。
- 原生事件与证明保留可复算性；大字段去重、压缩，避免依靠删除失败证据来缩小文件。
- 第一轮研究以 14–28 天为候选时间跨度，实际样本量、市场时段和覆盖决定是否足够。该跨度不是统计有效性承诺。

## 4. 总体数据流

```text
官方资产响应 → 不可变股票名单版本
                         ↓
已核验协议清单 → 独立建池日志扫描 → 固定区块目录快照 + 覆盖证明
                                           ↓
                    已有实时跟随 ← 受验证的目录登记
                                           ↓
选定历史区间 → 持久补采作业 → 去重事件 + 时间/报价/元数据证据
                                           ↓
                 可移植研究数据集 → 滚动窗口回放 → 分时训练/验证报告
```

目录初始化可以回到协议部署起点，但只读取建池事件；历史交易作业仅抓选定区间及必要前后文。在线 follow 保持有界增量计算，不因本计划加入每轮全历史重算。

## 5. 完整性与池目录合同

目录快照至少含 chainId、assetVersion、protocolVersion、targetAnchor、各来源区间、missing、excluded、sourceHash、providerCompletenessAssumption、池数与股票归因数。complete 仅表示已声明的资产、协议与固定 targetAnchor 内没有已知缺口，仍保留公共 RPC 未静默漏日志的既有假设。

- Factory/Manager 必须有明确地址和核验证据。未知部署起点保留 unknown；若采用从 0 扫描，报告该选择和代价。
- 不能把 token 名称、近期排行榜或一份任意第三方池表当身份与覆盖证明。
- V3 使用 chainId/protocol/address 为键；V4 使用 chainId/protocol/manager/poolId，不能按币对合并不同费率、hook 的池。
- 第一次目录构建固定启动时 head；完成后重新检查端点及有效分支，再标记完成。若需要当前 head 的目录，另起有界增量段，不无限追移动目标。
- 名单新增地址会改变覆盖要求。可复用已证明覆盖该 selector 的分片，但不能仅复制旧 scope 的 complete 标记。删除/停用的股票保留旧版本，研究时披露当前名单带来的回顾性选样偏差。
- 默认 follow 仍按 latest 启动。历史缺口由独立作业处理，不自动改变启动语义。

## 6. RPC 与作业恢复合同

复用现有限流、请求预算、证据写入和 ShutdownController。请求级两次重试后，目录/补采作业对明确的 timeout-or-network、rate-limit、http-transient 等临时失败进入 waiting-retry。等待使用可中断控制器，建议批次退避 2/4/8/16/30 秒，上限 30 秒，按成功完成一个区间重置。

不完整范围可以持久保存，但不能推进 accepted cursor，也不能据此登记业务池。成功范围不因后续失败被丢弃。达到本次 duration/call budget 后保留可续跑状态；新一次显式 resume 可使用新运行预算，累计实际消耗仍可查询。

身份错误、相同日志冲突、不可解析响应、证据写入失败、数据库失败不能被无限重试包装成普通网络抖动。停止和预算必须在排队、等待、派发前复查。任何恢复都不能跳过未完成范围。

暂不加入自动多供应商切换。若以后扩展，须先定义各供应商 chainId/anchor/canonicality 一致性与共享预算。

## 7. 存储合同

第一版使用现有 SQLite 和 Node 内置 gzip；先不引入 Parquet/对象存储服务。保留以后导出分区列式文件的接口，不作为本计划验收前置条件。

- 原始事件按现有链/块 hash/交易 hash/logIndex 身份去重；分叉版本与失败分片保留。
- 大的重复 JSON 通过内容 hash 引用压缩对象；hash 基于未压缩的规范字节，不基于 gzip 输出。
- 压缩格式有明确版本，读端先兼容旧 JSON 与新引用，再启用新写入。未知版本、缺失对象和 hash 不匹配必须失败，不视为空数据。
- batch 的原始 manifestHash 不因编码格式变化重算为“新事实”；扩展后的逻辑 batch 要与旧格式等价。
- 原始日志、完整性证明、时间锚点、资产/报价快照、业务状态及撤回依据不得抽样。
- 单纯 transport 调试证据可以沿用 full/sampled/off 的明确模式；sampled/off 不能标为完整请求归档。
- 第一轮不删除旧数据、不原地 VACUUM/重写生产库。紧凑迁移使用 SQLite 一致 backup 到新路径后操作；保留 WAL 已提交内容，旧源保持可用。
- 不按“每小时增长”承诺固定磁盘效果。离线报告分别列原始事件、目录、manifest、过滤条件、业务评估、调试文件、索引与备份。
- 同一固定夹具，目标数据库与外部运行文件总字节相较旧写法减少至少 50%，同时保证逻辑事件/覆盖/提醒等价；达不到时报告未通过，不减少证明字段凑指标。

## 8. 历史数据与研究合同

历史作业使用独立 study DB，优先复用完整本地证据，只补缺失 selector/区间。不得给实时时间线发送历史提醒，不因研究复制建立多个无法追踪的 DB 链。

研究配置固定：资产/协议版本、区块/日期界限、样本纳入规则、数据 hash、规则版本、训练/验证/测试时间段。业务采集时间与首次可获得时间分开。

- 数据必须包含热、冷、普通、短生命周期和无交易池；零活动必须有完整区间覆盖，缺数据是 unknown。
- 当前目录用于回看时标 retrospective-cohort；没有历史名单/配置/到达顺序时不能标 recorded-observed 等价或当时可知。
- 默认前文预热 180 分钟、结果观察 180 分钟，按实际规则需要校验足量报价上下文；不得用未来报价、当前 decimals 或当前公司行动乘数反填历史。
- 日志附加 blockTimestamp 不自动可信；事件仅有分钟位置时，滚动边界无法判断继续标 unknown。只补必要端点/分钟边界及需要精确时间的事件所在块，不逐块扫描所有 header。
- 统一当前 `(T-duration,T]` 的滚动 1m/5m/15m/1h。旧 minute-close 作为显式 legacy 对照保留，输出必须区分版本。
- 历史按链时间回放与实录按 observedAt 回放是两个模式：缺少真实观察顺序时可以研究链上热度，但不能声称测得实际提醒延迟。
- 热度候选从绝对成交量、相对自身基线倍数、去重交易数和持续时间出发。独立地址不等于独立用户；初版不新增不可靠的钱包人数指标。
- 结果输出后续 15/60/180 分钟成交/活跃/衰减、每日提醒数、重复提醒与短尖峰情况；保留未计价、缺口、右截尾。
- 时间拆分可配置且不重叠。训练 outcome 不越入验证区，预热只读此前数据；按池/股票报告分组依赖，不能把同一热点的多个滚动点当独立样本。
- 阈值只产生候选报告；不自动覆盖 `config/signals.initial.json`。效果不显著、样本不足也是有效研究结论。
