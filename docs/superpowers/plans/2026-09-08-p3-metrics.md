# P3 分钟成交与热度排名 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 产出池/RWA的成交、次数、放量倍率和流动性动作信息。

**Architecture:** 使用分钟归桶及事件顺序。计价可降级，费用只作可选毛费附注，排名不依赖LP收益模型。

**Tech Stack:** Node.js 24、TypeScript strict ESM、pnpm、viem、SQLite；协议格式优先官方 ABI/SDK。

## Global Constraints

- 只读链数据；生产热路径不依赖 Uni API、Subgraph 服务或 GMGN。
- Node.js 24、TypeScript strict ESM、pnpm；精确版本与 lockfile 由 P0 固化。
- 原始金额 bigint；持久化用无损字符串；业务结果绑定 chainId、blockHash 与版本。
- 实时与历史共用业务核心；缺口不补零，未知估值/费用不写零。
- 同块动态发现、断点恢复、重组与告警撤回必须有测试。
- 秘钥仅从本机环境读取；日志保存 provider alias，不保存带凭据 URL。
- 现有 research/、tooling/、.agents/、.pnpm-store/ 保留，不纳入应用依赖重构。
- 每窗口只实现指定阶段；更新状态和证据，未验收不得勾成完成。
- 默认只提供 RPC、本机增量同步；无付费索引后台依赖，记录调用用量与预算。

所有相对代码路径以 E:/lp-monitor 为根。架构依据：[设计](../specs/2026-09-08-robinhood-rwa-monitor-design.md)。下列代码块定义接口、关键算法和测试输入；实际实现需围绕这些合同补齐本阶段列出的行为，不是把文档片段原样拼成生产程序。命令均为未来阶段实现后的验收入口，本次写计划没有运行它们。

## Task 3.1：成交计价与统计单位

**Files:** 创建 src/metrics/notional.ts、src/metrics/price.ts、src/metrics/rwa-aggregate.ts、tests/unit/notional.test.ts、tests/unit/aggregation.test.ts。

**Interfaces:** valueSwap(swap,metadata,quotes): SwapValuation；结果含原币量、usdgNotionalRaw|null、usdMicros|null、计价侧、报价证据与质量。

- [ ] RWA/USDG取USDG侧一次；Meme/RWA取RWA侧，只有可用的先前报价才转换。数量用bigint，decimals缓存；USDG等同美元仅作显示假设。
- [ ] 测试USDG在0/1侧、两种decimals、报价未来/过期、缺失价格。分钟时间不精确时按年龄区间上界检查maxQuoteAgeSec=60，不为可疑报价填新时间。
- [ ] 比例换算核心如下，先检查raw>=0、decimals整数0..255、denominator>0。价格来自已核验纯SDK数学或同池Swap报价，不额外每笔eth_call。

~~~text
quoteMicros = raw * priceNumerator * 1_000_000 /
              (10^decimals * priceDenominator)
~~~

- [ ] 同tx跨两个池各有1笔Swap：两池swapCount各1；RWA聚合swapCount=2、txCount=1；poolActivity可相加，不能称独立用户成交额。Swap.sender不计真实人数。
- [ ] 首版只记录同tx共现线索，不实现完整路径图/trace归因。无价池保留原币量和次数，不同RWA原币量不能直接美元排名。
- [ ] 运行 pnpm exec vitest run tests/unit/notional.test.ts tests/unit/aggregation.test.ts。

## Task 3.2：分钟桶、基线与排名

**Files:** 创建 src/metrics/windows.ts、src/metrics/baseline.ts、src/metrics/ranking.ts、src/storage/migrations/003-metrics.sql、tests/unit/windows.test.ts、tests/integration/metrics-repair.test.ts。

**Interfaces:** buildMinuteMetrics(activeEvents,coverage,watermark): readonly MetricWindow[]；rankPools(windows,sortBy)支持volume5mClosed和volumeMultiplier。

- [ ] 记录本分钟partial、最近完整1m、最后5个完整1m合计、自然闭合5m桶；字段明确区分，不把partial冒充完整滚动60秒。
- [ ] 保存volume、swapCount、txCount、add/remove/zeroDelta动作数、活跃分钟数、baseline样本数、倍率。倍率只比较同池同单位同尺度的前置完整桶；基线0为null。
- [ ] 测试59秒/60秒边界、多块同秒、空分钟、缺覆盖、只完成部分地址分片；完整范围无日志可为0，失败覆盖为gap。minuteTime未知时分钟指标不可用，但块范围计数仍输出。
- [ ] closed必须同时满足：分钟两侧边界有效、同一scope完整覆盖该分钟全部块范围、解码与归桶无缺项。测试少扫1块或缺1个过滤分片时即使无日志也不可closed；自然5m必须五分钟均closed，不能把partial加入历史基线。
- [ ] 旧Swap退出active或时间归桶修正时重算受影响分钟和后续依赖基线；跨池txCount重新求集合，不相加各分钟unique计数冒充更长窗unique。
- [ ] 排名先有价池按5m量，另给倍率榜和新池/再热标签；不把raw L或未验证LP APY混成评分。同分使用txCount和稳定poolId排序。
- [ ] 运行 pnpm exec vitest run tests/unit/windows.test.ts tests/integration/metrics-repair.test.ts。
